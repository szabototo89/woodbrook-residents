## Goal

Keep the same logo size and menu geometry when visitors change pages. Preserve active links and the accessible phone menu.

## Technical changes

Baseline: `7006686127bdaebafde3320471fb5546ea0e3d3f`. The implementation commit is recorded above.

| Area             | Before                                                                     | After                                                                                | Why                                                 | Code                                                                             |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------- | -------------------------------------------------------------------------------- |
| Shared component | Header already serves every page from the site feature directory           | Shared header lives under components and remains in the root layout                  | Keep application chrome separate from page features | `apps/laura-faichney-web/src/components/SiteHeader.tsx`, `src/routes/__root.tsx` |
| Header styles    | Base, responsive and motion rules are scattered through global CSS         | One adjacent stylesheet owns header rules                                            | Keep menu styling in one place                      | `src/components/SiteHeader.css`, `src/styles.css`                                |
| Page overrides   | Services and Contact change logo width, header height, margins and spacing | Page styles no longer override the header                                            | Match About across pages                            | `src/services-design.css`, `src/contact-design.css`                              |
| Narrow tablets   | The full menu extends past its container at 641px                          | Shared gaps and button padding keep it inside the container                          | Prevent overflow above the phone breakpoint         | `SiteHeader.css`                                                                 |
| Style delivery   | The inline stylesheet bundles three source files                           | It also bundles shared header CSS in development and production                      | Preserve styled server HTML and hydration           | `apps/laura-faichney-web/vite.config.ts`                                         |
| Regression       | No cross-page header geometry check                                        | Nine viewport checks compare all five pages; phone test covers Escape and navigation | Prevent page-specific header drift                  | `tests/e2e/shared-header.spec.ts`                                                |

## Architecture changes

Laura’s website presents the artist’s work and project enquiries. The root layout already renders one header for every route. This change relocates that component and consolidates its styles; component responsibilities and interactions remain the same.

| Level | Change                                                                                     | Evidence                                               |
| ----- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| C1    | Unchanged: the same visitors and external services use the website                         | Presentation-only change                               |
| C2    | Unchanged: the website, content store and enquiry provider remain the same                 | Same application and external dependencies             |
| C3    | Unchanged: the root layout still owns one shared header with logo, menu and contact action | Component relocation and stylesheet consolidation only |
