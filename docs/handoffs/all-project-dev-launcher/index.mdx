## Goal

Start every browser-based Woodbrook project with `bun run dev:all`, see which
projects are ready, and stop or restart one project without leaving the terminal
or disturbing the others. The launcher owns only the processes it starts.

## Technical changes

Baseline: `956a81e`. Implementation: `72b7b75`. Existing `dev` and `dev:<project>` commands remain available.

The mobile entry starts `bun run dev`, which runs its bundle server on 3202 and
its browser host on 3203. Readiness needs both. The web and mobile commands keep
the existing `--env-file=../../.env` behavior. Logs are an in-memory ring of 300
lines per project. The launcher never adopts, probes as ownership, or stops a
process it did not spawn.

## Architecture changes

Woodbrook is a public resident information hub. This change adds a local
development environment beside the deployed system: an engineer runs one
launcher, the launcher reads a committed project inventory, and it starts project
servers in owned process groups. The deployed website, content sources and
resident-facing boundaries do not change.

| Level | Change                                                                                                                                       | Evidence                                                                         |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| C1    | Added a local development system and represented existing project servers as one supervised group; the deployed product surface is unchanged | Context view; `scripts/dev/projects.ts`                                          |
| C2    | Added the Bun/OpenTUI launcher container; it reads the repository and owns project server child processes                                    | Container view; `scripts/dev/index.tsx`, `scripts/dev/process-manager.ts`        |
| C3    | Added inventory, lifecycle, interactive, streamed-output and CLI responsibilities; the UI controls the manager but never spawns processes    | Component view; `scripts/dev/ui/DevManagerApp.tsx`, `scripts/dev/interactive.ts` |
