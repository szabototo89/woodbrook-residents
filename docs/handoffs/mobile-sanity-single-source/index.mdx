## Goal

Residents receive published content from one editorial source on mobile and the website. [Issue #14](https://github.com/szabototo89/woodbrook-residents/issues/14) records the owner's Sanity-only scope update. Website pages still reflect their latest static build; mobile loads content at runtime.

## Technical changes

Baseline: `956a81e`. Implementation: `6af6d2d1defe47ff60fa39e7afff94cb0bb13d6b`. This handoff is a separate documentation change on the same branch.

| Area               | Before                                           | After                                                           | Why                                        | Code                                                         |
| ------------------ | ------------------------------------------------ | --------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| Mobile backend     | Worker constructs the Sheets adapter             | Worker passes runtime bindings to the shared factory            | Share website configuration and validation | `apps/web/src/worker.ts`, `contentSnapshot.ts`               |
| Source selection   | Sanity default with optional Sheets              | Sanity only; unsupported values fail                            | One editorial source                       | `contentSourceFactory.ts`, `scripts/deploy.ts`               |
| Published reads    | Queries rely on API defaults                     | Published perspective plus draft/release ID filters             | Protect token-authenticated public reads   | `sanityContentSource.ts`, `sanityQueries.ts`                 |
| Legacy integration | Sheets adapter, parser, credentials, commands    | Removed; unrelated Google dependencies remain                   | Remove unused content infrastructure       | `apps/web/package.json`, root `package.json`, `.env.example` |
| Regression checks  | Worker helper tests bypass real source selection | Actual Worker tests exercise Sanity transport and validation    | Catch deployed/development divergence      | `apps/web/src/worker.test.ts`                                |
| Setup              | Mobile README describes a Sheets backend         | Sanity defaults, server token and local/device paths documented | Keep secrets on backend                    | `apps/mobile/README.md`, `apps/web/README.md`                |

No CMS schema, dataset, mobile screen, production configuration, or content migration changes. GET cache headers, CORS, preflight, write rejection and asset serving retain their existing behavior. The public response includes settings when a published settings document exists; the real dataset currently has none.

Server configuration is documented in `apps/web/README.md`. Published-perspective semantics follow the [Sanity Query API](https://www.sanity.io/docs/http-reference/query) (accessed 29 October 2026).

## Architecture changes

Woodbrook provides community information for residents. Sanity Content Lake stores published records and private editorial work. The existing Website asset host serves static pages and a read-only mobile API; both mobile renderers continue to fetch that API.
