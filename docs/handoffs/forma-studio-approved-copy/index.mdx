## Goal

A prospective customer reads only approved copy on `/` and `/blog`. This handoff removes the footer statement "Forma Studio · Websites for local businesses", records the copy review for both pages, and keeps navigation and email actions unchanged.

## Technical changes

Baseline: `a86762b`. The footer statement was stored in the published Sanity document `siteSettings` and required by the web contract, so removal spans the Studio schema, the runtime contract, the seed, both renderers and the stored document.

| Area                | Before                                   | After                                                              | Why                                                           | Code                                                                  |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------- | --------------------------------------------------------------------- |
| Content contract    | `settings.footer` was required text      | The field is absent; a stored value is dropped by the contract     | Rendering must not depend on copy the studio no longer offers | `apps/forma-studio-web/src/features/content/schema.ts`                |
| Homepage footer     | Brand descriptor and service summary     | Service summary only                                               | Remove the reported line and keep the approved services copy  | `apps/forma-studio-web/src/features/home/HomePage.tsx`                |
| Journal footer      | Brand descriptor and link home           | Link home only                                                     | Remove the reported line without losing the route back        | `apps/forma-studio-web/src/features/blog/BlogPage.tsx`                |
| Studio editor       | Site settings offered a Footer field     | Site settings offers no footer statement                           | Editors cannot reintroduce the removed copy                   | `apps/forma-studio/schemaTypes/index.ts`, `editorialHelp.ts`          |
| Published content   | `siteSettings.footer` held the statement | The published document no longer stores it                         | The content store matches the approved contract               | Sanity project `ms27me7o`, dataset `production`                       |
| Migration seed      | Seed JSON carried the statement          | Seed JSON carries no footer statement                              | A rerun cannot restore removed copy                           | `apps/forma-studio-web/migration/legacy-content.json`                 |
| Regression coverage | Tests asserted the statement was visible | Tests assert both reported lines are absent and actions still work | Keep the removal from regressing                              | `HomePage.test.tsx`, `BlogPage.test.tsx`, `formaContent.test.ts`, e2e |

The second reported line, "Design preview · Contact address to be confirmed", does not exist in this application. Git history places it in the retired `apps/locale-web` footer (`858c374`), and neither the built HTML nor the production pages contain it. The review records it as not reproducible instead of inventing a replacement.

## Architecture changes

Forma Studio shows approved business copy to prospects, reads it from its own Sanity project at build time, and publishes static pages through Cloudflare Pages. The change removes one copy field from that boundary. No new element or interaction appears; the page, the editor, the contract and the stored settings lose the same statement.
