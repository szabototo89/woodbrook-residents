## Goal

Show Laura’s signature and colourful portrait in shared website links. Keep each page’s own title and description, and serve the image without JavaScript or authentication.

## Technical changes

Baseline: `7065be36d01b8d7facf7da40e9981dff14d70ea3`; implementation: `537f6f43c0b1f00c6cecff97a3ac16a6883f4e25`. This is a separate feature from the completed SEO and Search Console handoff. The user explicitly approves direct updates to main without a PR for this task.

| Area              | Before                                             | After                                                                                      | Why                                                    | Code                                                       |
| ----------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ | ---------------------------------------------------------- |
| Sharing artwork   | No dedicated sharing cover.                        | A versioned 1200×630 JPEG uses Laura’s signature, portrait and headline.                   | Keep branding readable at thumbnail size.              | `public/social/laura-faichney-share-v1.jpg` in Laura’s app |
| Page head         | Text sharing fields; small summary card; no image. | Open Graph image, MIME type, dimensions and alt text; large-image card and matching image. | Give crawlers a complete image contract.               | `apps/laura-faichney-web/src/app/siteMetadata.ts`          |
| Origin resolution | Page canonical uses the configured origin.         | The sharing image uses the same origin, including explicit previews.                       | Keep image URLs absolute and nested routes consistent. | `createPageHead` and metadata regression tests             |

Built-in image generation composes the existing logo and portrait references. The generated PNG remains in Codex storage; the optimised JPEG and [prompt](./assets/image-prompt.txt) are preserved in the workspace. No CMS content, new visitor tracking or platform account is added. Sharing platforms control rendering and may cache previous previews. Contract references: [Open Graph image properties](https://ogp.me/#structured) and [LinkedIn cached-preview guidance](https://www.linkedin.com/help/linkedin/answer/a6233775), accessed 8 November 2026.
