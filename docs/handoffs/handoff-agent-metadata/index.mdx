## Goal

A handoff records the context another engineer or coding agent needs to continue the work. That context is incomplete when it names the worktree and Git HEAD but not the coding agent or the agent session that produced it. This feature adds the coding agent and session to every handoff's frontmatter and displays both in the document header so the next agent can find the originating conversation.

Completed handoffs are historical records. This feature is documented in a new handoff rather than by rewriting the completed `agent-handoffs` document.

## Current state

- `HandoffMetadataValue` accepts `agent` and `session`; the viewer header renders them as **Coding agent** and **Session** with Lucide `Bot` and `Hash` icons.
- `HANDOFF.md` requires both fields in new handoffs and documents `opencode`, `codex` and `claude` as example values.
- Every repository handoff has non-empty `agent` and `session` frontmatter. Historical records that did not capture a session use `Not recorded` rather than inventing one.
- Existing completed handoffs keep their recorded content, evidence, screenshots, worktree, branch, commit and `updatedAt`. They received only the required metadata fields.
- The worktree cell spans the full metadata row, so the longer header stays readable at desktop, phone and narrow widths.

## Architecture

No new containers or components are introduced. The existing handoff document reader renders two additional frontmatter fields beside the recorded Git context; there are no service, data-store or C4 diagram changes.
