### Production blocker

Clerk's standard production setup requires a domain the operator owns and can add DNS records to, including authentication and email-sending records. The existing `workers.dev` address does not provide that DNS control. Clerk's Frontend API proxy option addresses the Frontend API connection, not the separate production email-domain requirements.

No production instance was created, no production settings or Cloudflare build variables were changed, and no website deployment was performed during this setup request. A development key must not be substituted for a completed production setup.

Production Google and Facebook connections also need their own provider credentials. Clerk's shared development OAuth credentials do not carry over to production. Email authentication can be configured independently once a valid production domain is available.

References: [Clerk production setup](https://clerk.com/docs/guides/development/deployment/production), [Frontend API proxying](https://clerk.com/docs/guides/dashboard/dns-domains/proxy-fapi), and [production email delivery](https://clerk.com/docs/guides/development/troubleshooting/email-deliverability), accessed 2026-10-21.
