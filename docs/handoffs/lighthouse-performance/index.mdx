## Goal

Fix the existing Lighthouse performance failures on all seven audited public routes, on mobile and desktop, while preserving the 90-point minimum in every category and the current visual design.

## Technical changes

Baseline: `3644734`. The failing CI report came from `2412d31`; the intervening account handoff and resize-test synchronization do not change public asset loading. Verified implementation: `a5b303b`.

| Area              | Before                                                                                    | After                                                                                                 | Why                                                                                 | Code                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Shared branding   | Every route downloaded a 1.26 MB PNG for a small logo                                     | Both header and footer use the same 128px lossless WebP, about 10 KB                                  | Match the display size at high pixel density and free bandwidth for initial content | `apps/web/src/components/AppHeader.tsx`, `AppFooter.tsx`, `public/images/woodbrook-logo-128.webp` |
| Home artwork      | Full-resolution seasonal illustration, note and coastal background exceeded 3 MB combined | Existing artwork encoded to smaller WebP assets with preserved transparency                           | Reduce competition with the hero and fonts; original assets retained                | `HomeHero.tsx`, `HomeEventCard.tsx`, `home.css`, `apps/web/public/images/`                        |
| Shared styles     | Four separate blocking stylesheets                                                        | One combined stylesheet preserves base, theme, home and auth cascade order                            | Reduce initial resource overhead without changing styles                            | `apps/web/src/app/site.css`, `apps/web/src/routes/__root.tsx`                                     |
| Fonts             | Latin body and heading fonts discovered after styles loaded                               | Anonymous WOFF2 preload hints use the same Vite-hashed URLs as CSS                                    | Discover the two visible fonts directly from HTML without duplicate transfers       | `apps/web/src/routes/__root.tsx`                                                                  |
| Audit preview     | Dynamic server-rendered preview fetched Sanity during each audited page load              | Verified static production output served by local Wrangler, with the same audit matrix and thresholds | Measure the deployed serving model and keep CMS failures visible at build time      | `apps/web/scripts/lighthouse.ts`, existing `build-static.ts`, `wrangler.jsonc`                    |
| Regression checks | No image transfer budget                                                                  | Browser tests fetch the image URLs actually rendered and enforce small logo/artwork budgets           | Catch reintroduction of full-resolution images through visible product markup       | `apps/web/tests/e2e/image-loading.spec.ts`                                                        |

The image encoder is an isolated local Pillow tool, not a runtime or repository dependency. It resizes copies with Lanczos and encodes WebP method 6; the logo is lossless, the note and seasonal illustration use quality 85. The hero and darkened coastal fallback use quality 60; its responsive width hint matches the 85% mobile / 67% desktop image region. The note is 400px wide and the fallback background 768px wide. The illustrated event is marked before its child image is parsed so its covered background is never requested. No new artwork, local facts or content source changes were introduced. Lighthouse routes, simulated mobile network, CPU throttling and score thresholds remain unchanged. The harness now runs `build:static` and `wrangler dev --local`, matching production static asset serving. The previous dynamic preview made live Sanity requests during audits; an observed local-info request waited 13 seconds before responding. The content source is still Sanity and is validated while building.

Exact source/output sizes, dimensions and encoding settings are recorded in `assets/image-encodings.json`. The 768px fallback is approximately 43 KB; it remains available for events without an illustration. The decorative note is approximately 9 KB, and the seasonal illustration approximately 55 KB.

## Architecture changes

Woodbrook is a public information and action hub for residents in Shankill. TanStack Start renders its browser interface; Vite prepares versioned assets, and Cloudflare serves the static production website. This change shortens the same browser asset-loading path without adding services.

| Level | Change                                                                                                                                     | Evidence                                                                     |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| C1    | Unchanged: same residents, public website and external content/authentication systems                                                      | No new system or actor; public routes remain the same                        |
| C2    | Unchanged: same browser application, build and Cloudflare asset host; smaller image payloads and fewer initial stylesheet requests         | Existing static build and `wrangler.jsonc`; root resource hints              |
| C3    | Unchanged: header, footer and home components keep their responsibilities and interfaces; they select optimized copies of existing artwork | Six focused asset URL substitutions; CSS cascade preserved in `app/site.css` |

No new C4 diagram is needed: the architectural boundaries and interactions are unchanged, and the request/payload changes are recorded in the technical table.
