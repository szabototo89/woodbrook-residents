## Goal

Woodbrook is a public information and action hub for residents of Shankill, Ireland. Residents should be able to create and manage an optional account while browsing community information freely. Migrate account access from Clerk to Firebase Authentication, using the existing `woodbrook.shankill.workers.dev` website without purchasing a domain or hosting an authentication server.

## Current state

The migration code was verified, merged into local `main` at `a3dadf7`, and deployed to the existing Cloudflare Worker on 2026-10-21 as version `e057a7f5-e61f-478b-adcf-cdd13a04890b`. The public review URL is [Firebase login](https://woodbrook.shankill.workers.dev/login/?feature_flag=firebase-auth); accounts stay off without the flag.

The browser integration uses the official Firebase JavaScript SDK. Clerk imports, dependency, configuration and account components have been removed from the web application. The historical Clerk handoff remains unchanged by this migration.

- `?feature_flag=firebase-auth` enables account navigation and `/login`, `/register`, and `/forgot-password`; the flag survives public navigation. The old Clerk flag no longer enables accounts. `VITE_FIREBASE_AUTH_ENABLED=true` enables accounts for everyone; the shipped default is off.
- Registration creates an email/password account, saves the display name and requests an email verification link. Signed-in residents can change their display name, resend verification, request a password reset and sign out. Sessions persist through reloads. Recovery uses Firebase's managed email action page to choose the new password.
- Shared request state prevents duplicate requests and preserves errors even when account creation succeeds before email delivery fails. Delayed profile updates respect the current session, including sign-out in another tab.
- Firebase project `woodbrook-auth-20261021` is on the no-cost Spark plan. Email/password and Google are enabled. The project authorizes the current `workers.dev` address and localhost, requires passwords of at least eight characters, and enables email enumeration protection. Phone and anonymous sign-in are disabled. Google uses the support email explicitly approved by the user.
- The public project profile in `firebaseProject.json` makes builds repeatable. Environment variables can override the profile. No service-account credential or OAuth client secret is committed. Google is shown by default when the account feature is enabled; Facebook stays hidden because a production Meta application ID and secret have not been supplied to Firebase.
- A count-only check found one Clerk account. The user explicitly requested leaving it untouched. No account record, password or private metadata was exported or transferred, and no Clerk application/user was deleted. Firebase accounts are separate.

See [Firebase feature and setup guide](../../features/firebase-authentication.md) for project overrides, provider setup, rollout and scope.

## Architecture

Firebase Authentication is Google's managed identity service: it stores account identities, verifies email, manages passwords and issues authentication sessions. The Woodbrook website remains a static browser application served by a Cloudflare Worker. A C4 container below means a running application or data store; it does not mean a Docker container. Account feature flags control interface availability, not authorization for private APIs. Existing issue-report privacy rules are unchanged.
