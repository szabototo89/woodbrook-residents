## Goal

Editors manage Forma copy, images and metadata without application edits. The site keeps its existing design, static pages and email enquiry flow.

## Technical changes

Baseline: `c0e96a4221951871b72c27a5cad5e3ecb1167058`; implementation commit `a76e609` is recorded in the header. The final integration also preserves main `107d1b2` and its strict TypeScript gates. Sanity is the content editor and store. Zod checks unknown data at runtime before the application consumes it.

| Area               | Before                                            | After                                                                                 | Why                                                         | Code                                                                                     |
| ------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Editing            | Local TypeScript and component copy               | Dedicated project `ms27me7o`, dataset `production`, and hosted Studio                 | Keep Forma separate from resident content                   | `apps/forma-studio/sanity.config.ts`                                                     |
| Editorial guidance | No Forma forms                                    | Plain-language descriptions on every custom field                                     | Explain location, input and publishing to regular editors   | `apps/forma-studio/schemaTypes/editorialHelp.ts`                                         |

| Build              | Prerenders local copy                             | Fetches and validates before emitting one virtual snapshot                            | Failed content prevents a new deployment; no fallback       | `apps/forma-studio-web/vite.config.ts`                                                   |
| UI and metadata    | Hardcoded copy and local image URLs               | Shared parsed snapshot supplies both routes, metadata and chrome                      | Keep design and behavior while enabling editing             | `apps/forma-studio-web/src/features/content/content.ts`, `pageHead.ts`, `home/`, `blog/` |
| Migration          | Existing public copy and editorial draft comments | Creates missing documents, native image assets and guide drafts; retains source dates | Preserve current copy and editor changes on reruns          | `apps/forma-studio-web/scripts/migrateContent.ts`, `migrationDocuments.ts`               |
| Rebuild            | Push and manual workflow                          | Also accepts isolated `forma-sanity-update` dispatch                                  | Support Forma publishing without selecting Laura's workflow | `.github/workflows/deploy-forma-studio.yml`                                              |
| Agent guidance     | No content-layer guide                            | Documents ownership, identifiers, data flow and field-change checklist                | Let a new coding agent extend the contract safely           | `apps/forma-studio-web/src/features/content/README.md`                                   |

Services, packages, process steps and FAQs publish with the homepage. Work and guides use independent referenced documents. Existing public guides retain published copies, matching drafts and a `needs-review` marker. This marker does not control publication. Required missing references fail the build; absent optional guide images use the existing icon.

The build token stays outside the module graph. Only parsed content enters the public bundles. No browser content-API calls or enquiry-submission service are added. Images load from Sanity's public image CDN. Migration input is used only by the explicit migration command and offline tests.

## Architecture changes

Forma helps prospective customers understand website services and enquire by email. The new editor and content store introduce a publishing boundary. A fresh, published snapshot must pass validation before static output reaches Cloudflare Pages. Manual rebuilds are supported; automated webhook delivery is operator setup, not an active new interaction.
