## Goal

Help residents manage optional private location details with less visual separation and clearer actions. Keep existing account access and storage behavior.

## Technical changes

Baseline: `3644734`. Implementation: `dd6d6dd591caf3d9eb55f19984ed5b893b079ae6`. Session HEAD `b924cb4` integrates local main `05e30ba`; the documentation commit adds this record and refreshed screenshots.

| Area              | Before                           | After                                                            | Why                                              | Code                                                   |
| ----------------- | -------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------ |
| Page layout       | Large hero beside a narrow form  | Compact heading, account navigation and wider form               | Keep context and task together                   | `apps/web/src/features/account/AccountDetailsPage.tsx` |
| Responsive styles | Shared login layout              | Scoped account layout with stacked phone navigation              | Fit settings and inputs to available space       | `apps/web/src/features/account/accountDetails.css`     |

| Validation        | General form alert               | Focus invalid Eircode and associate its alert with the input     | Help keyboard and screen-reader users fix errors | `AccountDetailsForm.tsx`                               |
| Actions           | Save and removal appear together | Separate save area and conditional removal section               | Clarify each action and its effect               | `AccountDetailsForm.tsx`                               |
| Privacy           | Repeated explanatory copy        | One privacy note and a short private badge                       | Retain reassurance while reducing repetition     | `AccountDetailsPage.tsx`                               |

The handoff index browser test assumed one historical title was alphabetically first. The new account handoff exposed that assumption. It now checks the full title order from the displayed document set.

No dependencies, migrations, routes, feature flags, authentication contracts or Firestore rules change. The location form retains its analytics mask and explicit Firestore server reads without persistent caching.

### Research and design decisions

Sources accessed on 22 October 2026. These are design-system recommendations, not evidence of resident usability testing.

- [GOV.UK question pages](https://design-system.service.gov.uk/patterns/question-pages/) recommends optional labels and short help text. Both optional labels remain; Eircode guidance is shorter.
- [GOV.UK buttons](https://design-system.service.gov.uk/components/button/) recommends a clear action hierarchy and reserves warning buttons for serious irreversible consequences. Save is primary; reversible location removal stays secondary.
- [W3C form notifications](https://www.w3.org/WAI/tutorials/forms/notifications/) recommends explaining errors and confirming successful submissions. The Eircode input references its alert; save and removal results are announced.

The settings navigation, reduced heading and wider panel are design judgments for this page. Resident usability testing remains outside this implementation.

## Architecture changes

Woodbrook is a public information hub. Its browser application uses Firebase Authentication for identity and Cloud Firestore for private location documents. This change stays inside the existing account presentation responsibility.
