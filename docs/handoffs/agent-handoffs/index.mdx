Woodbrook is a public information and action hub for residents. This handoff describes a separate engineering tool, not a resident-facing feature: a browser reader for implementation notes, screenshots, test results and architecture. A handoff records the context another engineer or coding agent needs to continue the work. Documents use MDX, which combines Markdown text with React components.

Keep that feature context in `woodbrook/docs/handoffs/` and make it readable in a browser. Use the independent viewer and the small template in the repository's `HANDOFF.md`.

Decisions: keep the viewer in apps/handoffs, independent of the public website; reuse React and Vite; use MDX and remark-gfm for documents and C4-PlantUML for architecture diagrams. Render diagrams locally to SVG with PlantUML 1.2026.9 and the bundled C4 library. The browser loads versioned assets and needs no diagram service, Java runtime or client renderer. Documents are trusted repository code, compiled at build time. This feature adds no editor or upload endpoint.

The index keeps orientation copy and controls in a sticky left column beside the document cards. Search, ranges and sorting are client-side because the document inventory is built at compile time. Time windows use each document's UTC `updatedAt`; undated documents appear only under All and sort after dated documents. Lucide icons supplement visible labels rather than replacing them, so status, actions and metadata remain understandable without color or icon recognition.

The October 2026 diagram update replaces all six existing Mermaid C4 diagrams across this handoff and the Clerk handoff. It changes presentation only; the Clerk diagrams retain their original recorded architecture and readiness context.

The shared inventory in `docs/architecture/c4-model.json` now supplies consistent names, responsibilities, boundaries and relationships to every diagram. Zod validates the inventory and references; PlantUML sources are generated from it, and the build rejects stale sources. All descriptions assume a new engineer who does not know the product. ## Index discovery

The landing page separates orientation from browsing. The left column holds the purpose statement, search, update windows and sort control; the right column lists one card per document with status, UTC update time, summary and a single open action. The layout becomes one column on tablets and phones.

- Search matches title, summary and status, ignoring case and surrounding whitespace. Clear and Escape restore the full list.
- Update windows use `updatedAt` relative to the current time. All includes undated documents; the 7, 30 and 90-day windows do not.
- Newest and oldest put undated documents last; title sorts A–Z.
- Filters combine. The count announces the visible subset, and both empty states offer Show all handoffs.
- Icons supplement visible labels: status badges, filter labels, the card action, metadata, outline, gallery and diagram controls.
- On phones, gallery previous/next controls occupy their own row above a centred full-size link so their labels do not wrap.
