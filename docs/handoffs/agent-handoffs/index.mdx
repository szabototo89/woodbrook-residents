## Goal

Woodbrook is a public information and action hub for residents. This handoff describes a separate engineering tool, not a resident-facing feature: a browser reader for implementation notes, screenshots, test results and architecture. A handoff records the context another engineer or coding agent needs to continue the work. Documents use MDX, which combines Markdown text with React components.

Keep that feature context in `woodbrook/docs/handoffs/` and make it readable in a browser. Use the independent viewer and the small template in the repository's `HANDOFF.md`.

Decisions: keep the viewer in apps/handoffs, independent of the public website; reuse React and Vite; use MDX and remark-gfm for documents and C4-PlantUML for architecture diagrams. Render diagrams locally to SVG with PlantUML 1.2026.9 and the bundled C4 library. The browser loads versioned assets and needs no diagram service, Java runtime or client renderer. Documents are trusted repository code, compiled at build time. This feature adds no editor or upload endpoint.

The October 2026 diagram update replaces all six existing Mermaid C4 diagrams across this handoff and the Clerk handoff. It changes presentation only; the Clerk diagrams retain their original recorded architecture and readiness context.

The shared inventory in `docs/architecture/c4-model.json` now supplies consistent names, responsibilities, boundaries and relationships to every diagram. Zod validates the inventory and references; PlantUML sources are generated from it, and the build rejects stale sources. All descriptions assume a new engineer who does not know the product. The Clerk context/container views consistently show one account service; environment readiness remains documented in that handoff rather than being modeled as separate software systems.

## Appearance

The reader uses a compact Git context header, section shortcuts, and a comfortable text width. Tables scroll within the document on phones.
