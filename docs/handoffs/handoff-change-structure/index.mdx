## Goal

Make a handoff explain the engineering delta: what changed, why it changed, which architecture responsibilities and interactions it affects, and what evidence verifies it. Enforce the same structure for future handoffs through repository guidance and build checks.

## Technical changes

Baseline: `c41728e` on local main. This handoff compares the session changes with that commit. The header records the actual Git HEAD at authoring; the implementation commit is created after verification.

| Area                | Before                                                                    | After                                                                                                | Why                                                      | Code                                                                                                 |

| Parser dependency   | The MDX compiler was transitive through the Vite integration              | Declared directly as a development dependency for parsing                                            | Make the checker dependency explicit                     | `apps/handoffs/package.json`, `bun.lock`                                                             |

The checker parses Markdown with React (MDX) and GitHub-flavored Markdown tables. It does not execute document metadata or attempt to prove that a PASS claim is truthful; the author must record observed results and evidence. Build/typecheck failures name the handoff and the violated rule. New handoffs cannot opt out through a metadata flag.

C4 annotations belong to individual views, preserving canonical labels and all previous generated sources. Removed labels describe a retired path for comparison rather than an active dependency. This feature adds support for all three statuses; its own implementation introduces and changes responsibilities without removing a runtime component.

## Architecture changes

The engineering handoff tool lets engineers and coding agents review versioned implementation notes in a standalone browser reader. Its build tool compiles repository-authored MDX and local assets. C1/C2/C3 show system context, containers and components respectively: here a container is an application or data store, not a Docker image.
