## Goal

Give residents one clear place to edit their private location, with the fields and save action visible sooner on phones.

## Technical changes

Baseline: `5e5dfc6`. Implementation: `9a6d6df95b7d516282fe99c424b7065d8a4f32db`.

| Area             | Before                                          | After                                                                 | Why                                        | Code                                                                         |
| ---------------- | ----------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| Layout           | Wide panel beside account navigation            | One centered column, limited to 640px                                 | Give two fields a suitable reading width   | `apps/web/src/features/account/AccountDetailsPage.tsx`; `accountDetails.css` |
| Privacy          | Separate sidebar note and badge                 | One privacy line inside the form                                      | Keep reassurance beside the private inputs | `AccountDetailsForm.tsx`                                                     |
| Security link    | Navigation item beside the form                 | Secondary link below the form                                         | Keep the primary editing task clear        | `AccountDetailsPage.tsx`                                                     |
| Save state       | Save works without edits                        | Save enables after an edit; unchanged submissions do nothing          | Prevent duplicate writes and clarify state | `AccountDetailsForm.tsx`                                                     |
| Phone actions    | Save area uses a narrow content track           | Full-width idle save button; save and discard share an edited row     | Make the primary action easy to reach      | `accountDetails.css`                                                         |
| Copy and spacing | Repeated headings and large removal explanation | Short introduction, smaller address field and one removal explanation | Reduce scrolling and repeated information  | `AccountDetailsForm.tsx`; `accountDetails.css`                               |

No dependencies, routes, feature flags or stored fields change. Existing save, retry, discard, removal, privacy masking and validation focus remain.

The design follows the previously reviewed [GOV.UK form guidance](https://design-system.service.gov.uk/patterns/question-pages/) and [W3C form feedback guidance](https://www.w3.org/WAI/tutorials/forms/notifications/), accessed 22 October 2026. The single-column composition is a design judgment verified through browser layout checks and screenshot review.

## Architecture changes

Woodbrook is a public community hub. Its account editor uses Firebase Authentication for identity and Cloud Firestore for private location documents. This revision changes presentation and the local submit guard.

| Level | Change                                                                                                          | Evidence                                           |
| ----- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| C1    | Unchanged: residents use the same hub and identity service                                                      | `AccountDetailsAccess.tsx`                         |
| C2    | Unchanged: browser application and private document store keep their interfaces                                 | `accountDetailsStore.ts`                           |
| C3    | Unchanged: page, editor and store keep their responsibilities; only layout and unchanged-submit behavior change | `AccountDetailsPage.tsx`; `AccountDetailsForm.tsx` |

No architecture diagram is added because boundaries and dependencies do not change.
